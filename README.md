# easyLauncher 3.0

Лаунчер Minecraft Java Edition: прежде всего обычный удобный лаунчер (сборки, моды, миры), а игра с друзьями,
фоны и помощник — дополнительные возможности поверх него.

> **Состояние.** Код проверен автоматическими тестами и сквозными сценариями интерфейса на одном компьютере
> (localhost). Серверы Mojang, Modrinth и CurseForge, а также вход Microsoft в тестах **имитируются**;
> с настоящим Minecraft, на двух компьютерах и между разными сетями лаунчер ещё не проверялся. Подробно — в разделе
> «Что проверено».

## Для игрока

Слева шесть разделов: **Играть · Сборки · Моды · Миры · С друзьями · Настройки**. Помощник открывается отдельной
кнопкой внизу и ни для чего не обязателен.

**Играть.** На экране: выбранная сборка (меняется кнопкой сверху), большая кнопка «Играть» и миры этой сборки.
«Играть» открывает обычное главное меню Minecraft. При первом запуске лаунчер объясняет вход через Microsoft
(можно играть и без входа, офлайн) и скачивает игру и Java. Прогресс показывается по реальным данным: этап, файл и
объём. Следующие запуски начинаются сразу и без вопросов. «Продолжить «мир»» и плитки миров — отдельное действие:
игра запускается и сразу входит в выбранный мир (Minecraft 1.20+).

Ниже кнопки «Играть»:
- **Быстрые действия:** позвать друзей, добавить моды, папка игры, скриншоты, настройки сборки.
- **Справа:**
  - статистика: часы в игре, запуски, миры, скриншоты, моды, место на диске;
  - сколько модов можно обновить;
  - совет дня.
- **Миры** — крупными карточками с обложкой и кнопкой «Играть».
- **Последние скриншоты.** По клику снимок открывается крупно; его можно сделать фоном, обложкой сборки или мира.
- **История сессий:** когда, сколько, в каком мире и с кем.
- **Новости Minecraft** — список изменений Java Edition с сервера лаунчера Mojang. Формат неофициальный; без сети показываются сохранённые.
- **Другие сборки** — переключение и запуск в один клик.

Часы считаются по журналу `profiles/<сборка>/playlog.json`, который лаунчер ведёт с этой версии. Игра до обновления
в них не попадает.

**Сборки.** Карточки сборок: обложка, версия, загрузчик, число модов и кнопка «Играть». Новая сборка: название,
версия и тип — Vanilla или Fabric. В разделе «Дополнительно» — импорт из файла `.easypack`. Внутри сборки три
вкладки:
- **Моды** — поиск среди установленных, включение и выключение, обновление, закрепление версии, удаление,
  «Вернуть прежний состав».
- **Миры.**
- **Настройки** — название, память, версия игры, обложка, папки, экспорт, удаление.

Последняя выбранная сборка запоминается.

**Моды.** Каталог Modrinth и CurseForge: поиск, источник, категории, сортировка, «только совместимые с выбранной
сборкой». Сверху всегда видно, в какую сборку ставятся моды. «Установить» сам подбирает подходящий релиз и
зависимости. Если при этом нет конфликтов, вопросов и ручных файлов, мод ставится сразу, без диалога. Иначе
лаунчер показывает план изменений. Карточка мода открывается внутри раздела; «Назад» возвращает к тому же запросу,
фильтрам и месту в списке.

**Миры.** Миры хранятся внутри своей сборки (`profiles/<сборка>/game/saves`, как у обычного Minecraft). Поэтому мир
нельзя случайно открыть несовместимой сборкой. У мира есть:
- обложка;
- резервные копии (делаются сами перед значительными изменениями сборки и перед удалением);
- восстановление;
- папка;
- удаление с вводом названия.

**Старые версии.** В списке версий есть всё, что публикует Mojang: релизы, снапшоты, бета, альфа, Infdev и
rd-132211. Для них лаунчер сам берёт Java 8 и LWJGL 2. Моды ставятся только в сборки с загрузчиком, поэтому в
разделе «Моды» сборок Vanilla нет. Играть с друзьями можно с Minecraft 1.7.2: у более старых версий нет сервера,
который проверяет аккаунты Microsoft (старый сервис входа Mojang отключён).

**С друзьями.** Отдельный сценарий:
1. Выбери сборку и мир (или «Новый мир…») и нажми «Начать сессию».
2. Сервер Minecraft запустится на твоём ПК.
3. Создай ссылку-приглашение.

Хозяин запускает сессию с аккаунтом Microsoft. Для проверки P2P он может включить «Разрешить друзьям без
Microsoft»: тогда гости заходят под офлайн-никами, но по-прежнему только по приглашению, после допуска хозяином и
через белый список. Это тестовый режим — офлайн-ник не подтверждён Microsoft и его можно подделать.

Только в этом разделе видны состояние сервера, игроки, подключения друзей с фактическим маршрутом (напрямую, через
TURN или relay), приглашения, адреса в локальной сети и консоль. Друг вставляет ссылку, видит мир, версию и моды и
нажимает «Подготовить и присоединиться». Его сборка комнаты ставится отдельно от личных. Без сервера приглашений
лаунчер прямо пишет, что подключиться можно только из локальной сети.

После первого подключения сборка остаётся в разделе «Сборки друзей»: там видно хозяина и точный состав модов.
Она не смешивается с личными и не редактируется вручную; следующее приглашение того же хозяина обновляет её состав.
Обязательные библиотеки общих модов также передаются гостю, даже если каталог пометил саму библиотеку как optional.

**Фон и обложки.** Фон главного экрана: стандартный (нейтральный), своя картинка, или обложка / последний
скриншот выбранной сборки. Затемнение регулируется для читаемости.
- Обложка мира ставится из скриншота сама, только если связь подтверждена: снимок сделан во время запуска из
  easyLauncher, и журнал игры однозначно указывает этот мир.
- Иначе снимок считается просто «скриншотом сборки».
- Обложку можно выбрать вручную (своя картинка или скриншот сборки). Ручная обложка закрепляется, и автоматическое
  обновление её не меняет.
- Лаунчер не подставляет случайные картинки и не выдаёт рисунки за кадры из игры.

**Внешний вид.** «Настройки → Внешний вид» содержит шесть готовых тем:
- **Жидкое стекло** (по умолчанию) — живой цветной фон и полупрозрачные панели с размытием и бликом;
- **Аврора** — северное сияние и звёзды;
- **Неон** — светящиеся рамки и ретро-сетка;
- **Закат** — тёплые переливы;
- **Пиксель** — камень, земля и объёмные кнопки, как в Minecraft;
- **Минимализм** — строго и однотонно, без эффектов.

Поверх темы настраиваются:
- цвет акцента (8 готовых или свой);
- цветовая схема (тёмная, графит, чёрная, светлая);
- сила размытия;
- анимации (полные, сдержанные, выключены);
- масштаб 90–125%;
- скругления и шрифт;
- компактная боковая панель.

Живой фон двигается только с помощью трансформаций (без перерисовки), а при выключенных анимациях стоит на месте.

**Помощник.** Отдельная панель. Работает без ключей: по правилам, а с установленной локальной моделью
(llama.cpp) — лучше понимает свободные запросы. Умеет сам: собрать новую сборку под тему («сделай сборку с зомби и
оружием») — выбрать концепцию, версию игры и загрузчик, подобрать проверенные моды по игровым ролям, выделить память и настроить графику;
добавить или убрать моды; поднять FPS; разобрать вылет и починить его. Сначала показывает, что сделает, —
делает по одной кнопке. У предложения есть код варианта; «Другой вариант» меняет игровой состав, сохраняя совместимость. Подбор модов идёт по каталогу Modrinth (нужен интернет). Модель выгружается перед
запуском игры.

## Для разработчика

```bash
npm install
npm start              # приложение
npm test               # 95 тестов ядра, сети, каталога, помощника (Node, нужен JDK для части тестов)
npm run test:electron  # прямой путь WebRTC + переход на relay (нужен дисплей; на Linux: xvfb-run)
xvfb-run -a node test/electron/ui-e2e.js <папка>  # 10 пользовательских сценариев в Electron, два экземпляра (playwright)
npm run dist:win       # установщик Windows (NSIS)
```

### Сервер комнат (`server/`)

Нужен для приглашений через интернет, обмена служебными сообщениями, запасного relay и каталога CurseForge.
Сам мир на сервере **не** запускается — relay только пересылает байты к ПК хозяина.

```bash
cd server && npm install && PUBLIC_URL=https://rooms.example.com CF_API_KEY=... node index.js
# или: docker build -t easylauncher-server server && docker run -p 8787:8787 -e PUBLIC_URL=... easylauncher-server
```

Сервер должен быть доступен по **HTTPS** (например, Caddy: `rooms.example.com { reverse_proxy localhost:8787 }`):
лаунчер отказывается от приглашений с обычным HTTP, кроме `localhost`. Адрес сервера задаётся в «Настройки → Сеть»
или переменной `EASYLAUNCHER_BACKEND` при сборке.

| Переменная | Назначение |
|---|---|
| `PUBLIC_URL` | внешний адрес для ссылок-приглашений |
| `CF_API_KEY` | ключ CurseForge for Studios — хранится только на сервере, клиенту не передаётся |
| `STUN_URLS` | STUN для прямого соединения (по умолчанию `stun:stun.l.google.com:19302`) |
| `TURN_URLS`, `TURN_SECRET` | свой TURN (coturn, `use-auth-secret`) — временные учётные данные выдаются гостям |
| `RELAY_MAX_CONNS` | лимит relay-соединений на комнату |

**Расходы.** Сервер комнат — небольшая VPS. Relay и TURN передают весь игровой трафик гостей, которым не удалось
прямое соединение: трафик оплачивается владельцем сервера. Бесплатного безлимитного relay нет.

### CurseForge

Ключ API выдаётся разработчику по заявке (CurseForge for Studios, 3rd Party API Terms). Ключ, встроенный в
распространяемый клиент, секретным сделать нельзя, поэтому лаунчер ходит в CurseForge **только через прокси сервера
комнат**; пользователю ключ не нужен. Разрешены только эндпоинты поиска, проекта, файлов и категорий. Если автор
запретил распространение через сторонние приложения (`allowModDistribution=false`, нет `downloadUrl`), лаунчер не
восстанавливает ссылку по шаблону CDN: предлагает открыть официальную страницу, скачать файл и импортировать —
принимается только файл с совпадающим SHA-1. Для локальной разработки можно задать `EASYLAUNCHER_CF_API_KEY`.

### CurseForge без VPS (Cloudflare Workers)

Если сервер комнат не нужен, каталог CurseForge можно отдать через бесплатный Cloudflare Worker:
`cf-worker/worker.js` + ключ в секрете `CF_API_KEY`. Пошагово — `cf-worker/ИНСТРУКЦИЯ.md`. В лаунчере адрес задаётся
в «Настройки → Сеть → Каталог CurseForge» или вшивается в сборку (`package.json` → `easylauncher.cfProxy`).

### Вход через Microsoft

Нужно приложение в Azure (Personal Microsoft accounts, платформа Mobile and desktop, redirect
`https://login.microsoftonline.com/common/oauth2/nativeclient`) и одобрение Mojang (форма aka.ms/mce-reviewappid).
Client ID вшивается в сборку (`npm run configure -- --ms-client-id ...` → `package.json` → `easylauncher.msClientId`)
или задаётся `EASYLAUNCHER_MS_CLIENT_ID`.

## Как устроено

```
core/store.js        сборки: profiles/<id>/{profile.json, lock.json, game/, server/, worlds.json}
core/worlds.js       миры сборки (game/saves): список по level.dat, обложки, блокировка, копии, перенос старой схемы
core/nbt.js          чтение level.dat (NBT): название, режим, версия, последняя игра
core/sessionlog.js   журнал клиента: какой мир открыт и какие скриншоты сделаны в нём
core/launcher.js     «Играть» (главное меню / вход в мир / на сервер), сессия с друзьями, гость
core/server.js       сервер на ПК хозяина: EULA только после согласия, готовность по «Done», причины сбоев
core/mojang.js, fabric.js, http.js   версии, Java от Mojang, библиотеки, ассеты; докачка и проверка хешей
core/lock.js         lock-файл (источник:ID, версия, сторона, хеши, enabled), манифест комнаты, сравнение сборок
core/catalog/        Modrinth API v2 и CurseForge (через прокси) в общем формате
core/modplan.js      план: релиз под версию/загрузчик, рекурсивные зависимости, конфликты, дубликаты, закрепления
core/modinstall.js   общий кэш → проверка JAR → транзакция (журнал, откат, история составов), вкл/выкл модов
core/net/            сеть: session.js (комнаты, допуск), relay.js, webrtc.js (+ скрытое окно Chromium)
core/ai/             помощник: правила, строгая схема ответа модели, llama.cpp по запросу, сборщик сборок
core/services.js     связка для главного процесса; main.js/preload.js — IPC и easyimg://; renderer/ — интерфейс
server/              сервер комнат: приглашения, сигналинг, relay, ICE/TURN, прокси CurseForge
```

**Сборки и миры.**
- «Играть» не трогает сервер, EULA и миры: обычный запуск клиента.
- Сессия с друзьями открывает мир сборки сервером (`--universe <saves> --world <папка>`). Пока сервер работает, мир
  заблокирован: одиночный вход в него и вторая сессия запрещены.
- Копия работающего мира: `save-off` → `save-all flush` → ожидание «Saved the game» → архив → `save-on`.
- Копии лежат в `backups/<сборка>/<мир>`, вне папки сборки, и переживают её удаление.
- Значительные изменения сборки (смена версии игры или загрузчика, удаление модов, откат) — только после
  подтверждения и с копией миров. Простые добавления модов применяются сразу.
- Миры из схемы 2.x (`worlds/<id>`) при первом запуске переносятся в `saves` своих сборок.

**Сеть.** Три независимые части: (1) сервер комнат — обнаружение и служебные сообщения; (2) права входа — токен
приглашения (256 бит, срок, лимит входов, необязательный список ников, отзыв) → билет → подтверждение хозяином →
белый список Minecraft с проверкой аккаунта (или явно включённый хозяином тестовый режим для офлайн-гостей); (3) игровой трафик — транспорт. Гость сначала пробует прямой путь
(WebRTC, при наличии TURN — через него), при неудаче за 12 с — relay. Хозяин направляет любой поток только на
`127.0.0.1:<порт своего сервера>`; гость не выбирает адрес. Транспорт — отдельный модуль с общим контрактом
(`core/net/transport.js`): EOS или другой провайдер подключаются без изменений интерфейса.

**Помощник.** Модель только понимает запрос и формулирует пояснение. Ответ ограничен JSON-схемой (грамматика
llama.cpp) и повторно проверяется кодом: лишние поля, неизвестные темы, ссылки — ответ отбрасывается, работают
правила. Модель описывает концепцию, темп и ограничения, но не выбирает названия или ID модов: в план попадают
только проекты, найденные обычным кодом в каталоге. Логи — данные, а не команды; из них вычищаются пути пользователя и токены.
Известные ошибки (Java, память, зависимости, Mixin, драйвер, порт) распознают правила. Модель загружается при
обращении к помощнику, выгружается перед запуском игры и сервера и после 5 минут простоя.

Сборку собирает код (`core/ai/builder.js`), а не модель: стабильное техническое ядро и меняющаяся игровая часть
по концепции и ролям. Кандидаты оцениваются по соответствию, актуальности, популярности и недавним повторам;
`variantId` делает выбор воспроизводимым, а «Другой вариант» создаёт новый состав в главном процессе. Версия и загрузчик новой сборки — та пара, под которую есть больше всего нужных
модов. Подборка проходит обычный план (версии, зависимости, объявленные конфликты); не прошедшее проверку
убирается или заменяется модом той же роли (JEI → EMI). Задание помощника хранится в главном процессе;
интерфейс передаёт только его id (`ai:run`).

## Что проверено

**Десять пользовательских сценариев** (`test/electron/ui-e2e.js`). Это настоящее приложение Electron, которым
управляет Playwright. Хозяин и друг — два экземпляра на одном ПК. Имитируются: серверы Mojang, Fabric Meta,
Modrinth и CurseForge (локально, по их схемам) и вход Microsoft. Игра и сервер — поддельные Java-программы, не
Minecraft. Установка игры идёт настоящим конвейером лаунчера: загрузки, хеши, Java, прогресс.

| Сценарий | Результат |
|---|---|
| 1. Первый запуск: объяснение входа → вход → загрузка Java/библиотек/ресурсов с прогрессом → главное меню игры | пройден |
| 2. Повторный запуск: без диалогов и без сетевых запросов (`test/firstrun.test.js`) | пройден |
| 3. Новая сборка Fabric → «Установить» Create → Fabric API подтянут, без диалога | пройден |
| 4. Карточка мода → «Назад»: тот же запрос, сортировка, список и прокрутка | пройден |
| 5. Обновление (план 0.8.13 → 0.9.0), выключение зависимости с предупреждением, откат | пройден |
| 6. Вход сразу в мир; обложка из скриншота сессии; своя обложка закреплена и не меняется; фон из сборки | пройден |
| 7. Сессия с друзьями: новый мир → приглашение → друг подключился (напрямую) → у хозяина виден маршрут → завершение | пройден |
| 8. Всё перечисленное — без модели помощника; помощник отвечает по правилам и не выдумывает моды | пройден |

## Замеры

| Что | Значение | Условия |
|---|---|---|
| Установщик Windows (NSIS) | 112 МБ | Electron 44, локали ru/en-US, сжатие maximum |
| Приложение после установки | 322 МБ, из них код easyLauncher 0,7 МБ | остальное — Chromium и Node (Electron) |
| Память в простое | ~307 МБ PSS (8 процессов) | Linux, Xvfb, программная отрисовка; на Windows не измерялось |
| Движок ИИ и модель | не измерено | скачиваются отдельно; размер показывается перед загрузкой по данным GitHub и Hugging Face |
| Память при работе помощника и после выгрузки | не измерено с настоящей моделью | с имитацией: процесс полностью завершается, остаток 0 МБ |
| Файлы игры | не входят в установщик | Java, библиотеки, ассеты — общий кэш `shared/` с проверкой хешей |

**Electron или Tauri.** Почти весь размер — Electron. Tauri использует системный WebView (WebView2 обычно уже есть
в Windows 10/11; он тоже занимает место на диске и в памяти — просто не входит в наш установщик) и дал бы
установщик заметно меньше. Цена: главный процесс (запуск Java, сервер, загрузки, сеть) пришлось бы переписать на Rust
или возить Node отдельным процессом, а прямой путь WebRTC — реализовать нативно (сейчас используется встроенный
Chromium). Это не измерялось — сборки на Tauri нет. Рекомендация: оставить Electron для первой версии и вернуться к
вопросу после проверки сетевой части на реальных пользователях.

## Модель помощника

Кандидаты (`core/ai/manager.js`):
- Qwen2.5 1.5B Instruct Q4_K_M — по умолчанию;
- Qwen3 4B — рекомендуется при 12 ГБ ОЗУ и больше;
- Gemma 3 4B и Gemma 3n E2B — условия использования Gemma от Google показываются до установки;
- Qwen3 1.7B, Qwen3.5 0.8B, Qwen2.5 0.5B.

Для каждой модели перечислены запасные репозитории Hugging Face: если в первом нет файла Q4_K_M, берётся следующий.
Сравнение на 12 русских сценариях не проводилось — модели недоступны в среде разработки. Запуск:

```bash
node tools/ai-bench.js --llama <путь к llama-server> --model a.gguf --model b.gguf
```

Метрики: валидный JSON, верное намерение, темы и исключения, выдуманные названия, время ответа, пик памяти, память
после выгрузки. Модель выбирается по этой таблице, а не по размеру. Скачивается только CPU-сборка llama.cpp;
GPU-ускорители и полный офлайн-комплект с моделью внутри — отдельные варианты поставки.

## Что осталось и блокеры

- **Сервер комнат не развёрнут.** Нужен домен с HTTPS и VPS. Без него работают одиночная игра и подключение в
  локальной сети по адресу из «Подробнее» (с добавлением ника в белый список).
- **Стандартный фон.** Лицензированного снимка из игры в комплекте нет: по умолчанию — нейтральный фон. Свой
  снимок можно положить в `renderer/assets/default-bg.jpg` (см. `renderer/assets/README.md`).
- **Одобрение Mojang для Client ID Azure.** Без него вход Microsoft вернёт ошибку «приложение не одобрено».
- **TURN** — свой coturn для сетей, где не проходит прямое соединение (иначе остаётся relay через WebSocket).
- **EOS** не интегрирован; транспорт подключается через `core/net/transport.js`.
- **Импорт сборок** — только формат easyLauncher (`.easypack`); `.mrpack` и архивы CurseForge пока не читаются.
- **Forge, NeoForge, Quilt** ставятся их официальными установщиками и Meta-серверами; в среде разработки это проверено только на имитации (настоящие серверы Forge и Mojang оттуда недоступны).
- **Создание мира для одиночной игры** — в самой игре (как в официальном лаунчере); в лаунчере новый мир
  создаётся только для сессии с друзьями.
