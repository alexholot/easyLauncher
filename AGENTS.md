# AGENTS.md — руководство для ИИ-агентов (Claude, Codex, Cursor и др.)

Этот файл — первое, что нужно прочитать перед изменением кода. Здесь: что это за проект, как он устроен,
что уже сделано и проверено, что не сделано, правила работы и подводные камни. Подробности для игроков и
разработчиков — в `README.md`, разбор интерфейса — в `docs/UX-АНАЛИЗ.md`.

## 1. Что это

**easyLauncher** — лаунчер Minecraft Java Edition на Electron. Интерфейс полностью на русском.

Главная идея — **сборка** (build, в коде `profile`): своя версия игры + загрузчик модов + моды + свои миры.

Что умеет:
- запуск любой версии Minecraft из манифеста Mojang: от `rd-132211` до последних снапшотов;
- загрузчики Fabric, Quilt, Forge, NeoForge;
- каталог модов Modrinth и CurseForge с подбором зависимостей и планом изменений;
- миры внутри сборки: обложки, резервные копии;
- игра с друзьями: сервер на ПК хозяина, приглашение по ссылке, прямое соединение WebRTC или relay;
- необязательный локальный ИИ-помощник (llama.cpp + GGUF);
- темы оформления: живые (пещера, костёр, древний город, луг) с пиксельной панорамой и стеклянные;
- «Гардероб»: 3D-скин (skinview3d), анимации, слои, плащ/элитры, галерея образов, загрузка скина в профиль Minecraft;
- «Камера воспоминаний»: короткие ролики из игры (FFmpeg, только по включению игроком) — живой фон лаунчера, моменты (достижения и смерти) с секундами до события, «Фильм сессии»;
- миры (4.0): «Летопись мира», карта мира по файлам регионов с местами событий, «Машина времени» по копиям;
- «Почему тормозило» (разбор запуска с кнопками исправления), «Вызов другу» (код с целью-достижением и лимитом), свой скин у сборки, сезоны живого фона.

Владелец — русскоязычный игрок, не программист. Общение и все тексты интерфейса — **на русском**, простыми словами.

## 2. Как запустить и проверить

```bash
npm install
npm start                       # приложение (Electron)
npm test                        # все unit/интеграционные тесты (node --test), сейчас 186, нужен JDK для части тестов
xvfb-run -a node test/electron/ui-e2e.js <папка-для-скриншотов>   # 10 сценариев в настоящем Electron (Playwright)
npm run dist:win                # установщик Windows (NSIS) → dist/easyLauncher Setup <версия>.exe; перед ним tools/fetch-ffmpeg.js кладёт FFmpeg в ffmpeg-dist/
```

- **Перед каждым релизом** прогоняются `npm test` и `ui-e2e.js`; оба должны быть зелёными.
- **Версия** — в `package.json` (сейчас 4.5.3).
- **Журнал лаунчера** — `<корень>/logs/launcher.log`: ошибки всех IPC-вызовов и неперехваченные сбои (`logError` в `main.js`). Если игрок пишет «была ошибка» — попроси этот файл.
- **Картинки установщика** — `tools/installer-art.ps1` (Windows PowerShell 5.1, файл в UTF-8 с BOM) создаёт `build/icon.ico`, `installerSidebar.bmp`, `installerHeader.bmp`. Её поднимают при каждой выдаче установщика пользователю.
- **CI.** `.github/workflows/build.yml` по тегу `v*` собирает установщики под Windows, macOS и Linux. В CI это ни разу не запускалось.
- **Тестовые зависимости.** Тестам нужны `javac`/`java`: поддельные игра, сервер и установщик Forge — это Java-программы из `test/fixtures`. Без JDK такие тесты пропускаются (`t.skip`).

### Данные на диске
Корень: `EASYLAUNCHER_HOME` или `%APPDATA%/.easylauncher`.

- `settings.json` — настройки. Принимаются только известные ключи: whitelist в `Services.saveSettings`.
- `profiles/<pid>/`:
  - `profile.json`, `lock.json` — состав сборки;
  - `worlds.json` — метаданные миров;
  - `playlog.json` — журнал сессий;
  - `covers/`;
  - `game/` — папка игры: `saves`, `mods`, `screenshots`, `resources`;
  - `server/`.
- `shared/` — общее для всех сборок:
  - `versions`, `libraries`, `assets` (включая `virtual/legacy`), `runtime` — Java от Mojang;
  - `mod-cache`.
- `backups/<pid>/<папка мира>/` — копии миров.
- `ai/` — llama.cpp, модель, `state.json`, `variants.json` (локальная история применённых вариантов сборок).
- `backgrounds/` — фон лаунчера; `cache/` — новости Mojang.
- `skins/` — гардероб: `<id>.png`, `skins.json` (образы, выбранный), `account/` — текстуры скина и плащей аккаунта.
- `profiles/<pid>/chronicle.json` — летопись миров; `perf.json` — последний разбор тормозов; `maps/<hex папки>/r.X.Z.png` — плитки карты (перерисовываются, если регион новее).
- `challenges.json` — активный вызов и история; `memories/films/` — фильмы сессий.
- `memories/` — ролики камеры: `<id>.mp4`, `<id>.jpg` (превью), `index.json`; `ffmpeg/bin` — FFmpeg, `ffmpeg/state.json` — найденный кодировщик и способ захвата.

### Ключевые потоки
- **«Играть».** `renderer.play()` → IPC `mc:play` → `Services` → `Launcher.play()` → `prepareRuntime`: версия, Java, загрузчик, библиотеки и ассеты. Затем `prepareMods` и `startClient`. По умолчанию игра открывается в главном меню; вход сразу в мир — отдельное действие (quickPlay, Minecraft 1.20+).
- **Моды.** `planMods(pid, request)` → план показывается пользователю → `applyPlan(planId)`. Если нет вопросов, конфликтов и ручных файлов, «Установить» применяет план сразу.
- **С друзьями через EOS (основной путь с 3.7.0).** Если рядом с приложением есть `resources/eos/EOSSDK-Win64-Shipping.dll` и `eos.json` (при разработке — `eos-sdk/` и `eos.local.json`, оба в `.gitignore`), `settings.invites = 'eos'`. Хозяин входит в EOS по устройству (`EosPlatform.start`), ссылка — `easylauncher://join?e=<id хозяина>&t=<токен>`. Приглашения (срок, число, ники, отзыв) хранит хозяин (`EosHostSession`). Гость: `hello` с токеном → сборка комнаты → `join` → допуск (белый список) → `localListener` → потоки `mux.js` по P2P на `127.0.0.1:<порт сервера>`. Пакет EOS — до 1170 байт; окно отправки 512 КБ на поток.
- **С друзьями.** `startCoop`: сервер открывает мир сборки через `--universe` и `--world`. Включены `online-mode=true` и белый список. Комната регистрируется на сервере комнат; друг получает манифест сборки, лаунчер ставит ему те же моды и подключает напрямую (WebRTC) или через relay.
- **Помощник.** Модель возвращает только JSON по схеме: намерение, темы, термины поиска и творческий бриф (архетип, темп, сложность, ограничения). Названия и ID модов модель не выбирает: поиск, роли, зависимости и план делает обычный код. Без модели помощник работает по правилам.
  - `Services.ask` готовит **задание** целиком и возвращает его `task.id` и шаги; выполняет `Services.runTask` по IPC `ai:run` (одна кнопка). Задание хранится в главном процессе (`this.tasks`), из окна приходит только id.
  - Новая сборка (`newBuildTask`): «сделай/новую сборку», Vanilla, другая версия/загрузчик → `builder.rankTargets` (пара, под которую больше известных модов темы; NeoForge не для ≤1.20.1) → `pickMods` → `prefetch` → `planPruned` по `emptyLock`. Сборка создаётся только в `runTask`.
  - Варианты сборок: `variantId` задаёт воспроизводимый порядок игрового состава. Техническое ядро остаётся стабильным, контент выбирается по концепции и ролям взвешенно, а не первым результатом по скачиваниям. `ai:reroll` принимает только id задания и строит новый вариант в главном процессе. Применённые варианты записываются в `ai/variants.json` и получают штраф при следующих подборках.
  - `planPruned` убирает моды с ошибками плана (нет релиза, сломанная зависимость, конфликт — убирается позже выбранный) или ставит замену той же роли (`alts`: JEI → EMI). Сетевые ошибки не выкидывают моды — пауза и повтор.
  - Починка (`fixTask`): находки `diagnose()` несут `data` (id модов из журнала) → добавить зависимость, убрать несовместимый, обновить/убрать мод со сбоем Mixin, обновить всё, память +2 ГБ.
  - Уточняющие вопросы: новая сборка или добавление «по теме» без названий модов → `kind: 'clarify'`; окно присылает ответы третьим аргументом `ai:ask` (`cleanAnswers` пропускает только известные поля).
  - **Связи по файлам** (`modlinks.js`): каталог часто не знает об обязательных библиотеках (Artifacts → curios, expandability; Iron's Spells → playerAnimator). `runTask` → `resolveLinks`: файлы качаются в кэш, читаются, недостающее ищется `findLibrary` (Modrinth, затем CurseForge; тестовая версия, если стабильной нет), иначе мод убирается. Перед «Играть» (`play`) та же проверка: ошибка `MISSING_DEPS` с заданием-починкой `e.task`. Требования берутся из описания загрузчика сборки (`READS`): один JAR бывает сразу для Fabric и Forge.
  - Рецепты (`RECIPES`, `BASE` в `builder.js`) — slug Modrinth, сверены с настоящим каталогом в октябре 2026. Несуществующий slug не ломает подбор — просто не находится.
- **Камера воспоминаний.** Выключена по умолчанию (`settings.memories.record`). Событие `client running` → `Services.watchGame` → `Memories.gameStarted({pid процесса Java, level()})`. Такт раз в 5 с: время считается, только если активное окно принадлежит этому pid, не свёрнуто и игрок в мире (`tracker.current`). Первый ролик — после 3 мин игры, дальше раз в `interval` минут. Захват: `ddagrab` (один монитор) или `gdigrab`, кодировщик из пробы `h264_nvenc → amf → qsv → mf → libx264`, приоритет FFmpeg ниже обычного. Во время записи раз в секунду проверяется окно: потеря фокуса/сдвиг → «q», ролик < 6 с не сохраняется. Ролики отдаёт `easyimg://` с Range (`videoResponse` в `main.js`), только `.mp4` из `memories/` (`Services.mediaAllowed`).
- **Живой фон.** `Live.setScene(style)` — панорама только у живых тем, `Live.setClips(list, on)` — ролики с перекрёстным затуханием, `Live.setPaused(игра запущена)` — фон замирает, пока открыт Minecraft. `data-live` на `<html>`: `panorama`/`video`/`off`.
- **Гардероб.** skinview3d грузится лениво (`vendor/skinview3d.bundle.js`). Картинки в WebGL — только через `skins:read` (байты из ядра → Blob → canvas): `easyimg://` даёт «испорченную» картинку, WebGL её не принимает. Скин из окна приходит байтами (перетаскивание), ядро проверяет PNG 64×64/64×32 и ≤512 КБ.
- **События.** `launcher.emit('event', …)` → `Services` → `main.js`. Там события `stage` и `mods-progress` прореживаются до раза в 100 мс, журнал `log` не пересылается. Дальше — в `renderer` через `bridge.onEvent`.

## 5. Что не сделано и блокеры

- **EOS проверен только на одном ПК** (два игрока EOS в разных процессах, 1 МБ туда-обратно, ~30 мс). Игру двух компьютеров в разных сетях и настоящий Minecraft через туннель EOS проверяют хозяин с другом. Ключи EOS (`clientSecret`) встраиваются в установщик — это нормально для политики Peer2Peer, но в git их не класть.

- **Client ID Azure** (`fab588dc-…`) вшит. Нужно одобрение Mojang, иначе вход вернёт «приложение не одобрено».
- **TURN-сервер** не настроен.
- **Импорт** только `.easypack`. `.mrpack` и архивы CurseForge не читаются.
- **Стандартный фон без лицензированного снимка.** Свой можно положить в `renderer/assets/default-bg.jpg`.
- **Не проверено на реальной сети:**
  - вход Microsoft (настоящий Minecraft, Forge и Fabric на Windows 11 проверены с офлайн-ником, см. таблицу);
  - NeoForge, Quilt и старые версии в настоящей игре;
  - установщик .exe на чистой Windows;
  - настоящие модели ИИ;
  - лента новостей Mojang.

  Если пользователь присылает ошибку оттуда — это первое, что нужно чинить.

## 6. Правила работы в этом репозитории

1. **Секреты.**
   - **Никогда** не записывай ключи и токены в файлы репозитория, сборки и архивы.
   - Ключ CurseForge хранится только в секрете Cloudflare Worker (`CF_API_KEY`) или в `server/.env`, который в `.gitignore`.
   - Перед коммитом и сборкой проверь: `grep -rE 'cfc_pat_[A-Za-z0-9]{8}|\$2a\$10\$[A-Za-z0-9./]{20}'`. В `server/check-curseforge.js` есть только проверки префиксов — это нормально.
2. **Язык.** Тексты интерфейса, комментарии и сообщения об ошибках — на русском, понятные игроку. Ошибки ядра — `fail(code, message, action)`: что случилось и что сделать.
3. **Честность.**
   - Не выдумывай проценты, пинг и игроков, в интерфейсе нет демо-таймеров.
   - То, что проверено только на имитации, так и называй.
   - В отчётах пользователю разделяй «проверено» и «не проверено».
4. **Стиль кода.**
   - Повторяй окружающий код: CommonJS, `'use strict'`, 2 пробела, одинарные кавычки, короткие русские комментарии «почему», без лишних абстракций.
   - Шаблоны HTML в `app.js` — строки с `esc()` для **любых** внешних данных.
5. **Безопасность Electron.**
   - Новый IPC-канал добавляется в `main.js` (`handle`) **и** в белый список `preload.js`.
   - Данные из окна интерфейса не доверенные: пути проверяются (`ownShot`, `imageAllowed`, `checkId`, `checkFolder`), адреса загрузок берутся из ядра, а не из UI. Пример — `ai:install` принимает только план из `ai:plan`.
   - Внешние ссылки — только из белого списка в `open:external`.
   - Картинки — через `easyimg://` и только внутри корня лаунчера.
   - CSP задан в `index.html`. Новый внешний источник картинок добавляется в `img-src`.
   - Внешний HTML (новости, описания) не вставляется как есть: из него берётся только текст.
6. **Интерфейс.**
   - Перерисовка — `render()`. Асинхронные отрисовки сверяют `renderSeq`/`stale(n)`, чтобы не затирать новый экран.
   - Новые поверхности должны выглядеть во всех темах. Класс добавляется в списки селекторов glass/pixel/light в `styles.css`: искать `:is(.panel, .card,`. Затем проверь скриншотами, какая тема включена: `settings.appearance`.
   - Ширина от 1000 px, без горизонтальной прокрутки.
7. **Тесты.**
   - Любое изменение ядра — с тестом в `test/*.test.js`.
   - Сеть подменяется через `http.setFetch()`, Mojang/Fabric/Forge — через `createFakeMojang()`, каталоги — через `createMock()`.
   - Тесты не ходят в интернет.
8. **Релиз пользователю.**
   - Поднять версию → `npm test` → `ui-e2e.js` → `npm run dist:win`.
   - Скопировать установщик в `/home/user/release/easyLauncher-Setup-<версия>.exe`, если работаешь в той же среде.
   - Отчёт на русском: что исправлено, что проверено, что нет.
9. **Git.** Репозиторий приватный: `github.com/alexholot/easyLauncher`, ветка `main`. Установщики (>100 МБ) в git не коммитятся — только в GitHub Releases.

Бесплатный сервер засыпает после ~15 минут без запросов: первый запрос после сна ждёт около минуты; комнаты хранятся в памяти и при перезапуске пропадают.

Для `http.download` это обрывало любой файл, который качается дольше: модель ИИ (ГБ), Java, установщик Forge на медленном интернете — 4 попытки по 30 с, и «Файл не скачан». LGPL, а не GPL: её можно распространять рядом с программой, а libx264 не нужен — есть кодировщики видеокарт и `h264_mf` (кодировщик Windows). Скачивание из окна камеры осталось запасным путём для сборок без `ffmpeg-dist`.
- **`h264_mf -hw_encoding 1` на ПК с NVIDIA не открывается** («format negotiation failed»), а проба без этого флага проходила — запись падала после удачной пробы. Проба идёт с теми же настройками, что и запись; `h264_mf` — без флага. Кодировщик ищется заново, если сменился ffmpeg.exe (`state.exe`).
- **Первая запись после установки** иногда возвращала «Nothing was written» обоими способами захвата (похоже на проверку антивирусом свежих библиотек FFmpeg); повтор через 2 с проходит, поэтому в `record` есть одна повторная попытка.
- **Светлая тема поверх ролика:** на главной текст принудительно светлый, поэтому панели там становятся тёмным стеклом; на остальных экранах под текстом вуаль цвета `--bg`. Иначе в «Дневном луге» белый текст оказывался на белых панелях.
- **Моменты (3.9.2).** `sessionlog.parseMoment` находит в журнале игры достижения/испытания/цели и смерти игрока (ник передаётся в `SessionTracker`). Форматы: 26.x — сервер пишет `System chat: …`, клиент — `[System] [CHAT] …` (одно событие дважды — склеивается за 5 с), старые версии — без префикса, официальный журнал — XML (текст в CDATA). Русские строки взяты из `ru_ru.json` Mojang: «получил достижение «[…]»», «завершил испытание», «достиг цели». Смерть — системное сообщение чата, начинающееся с ника (кроме входа/выхода), без пометки чата — по глаголам.
- **Буфер моментов:** `ddagrab` → NVENC/AMF напрямую (без `hwdownload`, ~1% одного ядра), кольцо `memories/buffer/buf00..14.ts` по 2 с и список готовых кусков `list.csv` (его ведёт FFmpeg — недописанный кусок туда не попадает; по времени файлов сортировать нельзя: у двух файлов одно время). Ролик = копия последних кусков + `concat -c copy`, разрешение — как у окна игры (`scale_d3d11` в FFmpeg 9 с кадрами ddagrab не заработал). Если буфер падает в первые 5 с — `state.zeroCopy=false`, дальше моменты пишутся после события. Пауза между моментами 45 с; буфер идёт, только пока окно игры активно и игрок в мире; ролики по расписанию при буфере вырезаются из него же.
- **Скругления (`data-radius`) и темы:** своё `--radius` или `border-radius` темы задаётся только под `[data-radius="normal"]` — иначе правило темы (позже в файле, та же специфичность) перебивает выбор игрока; так в 3.9.0–3.9.2 «Острые/Круглые» не работали в живых темах. «Острые/Круглые» меняют все поверхности через общий список в конце `live.css` (`--radius` для панелей, `--r-ctl` для кнопок и полей). Новая поверхность — добавь класс в этот список. В «Пикселе» углы всегда прямые.
- **Цветовая схема (`data-theme`) и «Стекло» (`data-blur`) в живых темах (3.9.4):** токены темы (`:root[data-style=lush]`) перебивали схему — «Графит/Чёрная/Светлая» не работали, как и скругления до 3.9.3. Теперь схемы живых тем заданы отдельно с большей специфичностью (`:root:is(живые)[data-theme=…]`), «Светлая» — общая для всех четырёх (у луга она по умолчанию), пещеры в ней уходят под светлую вуаль, «Дневной луг» в тёмных схемах — ночной луг (`Live.setScene(style, theme)` → `SCENES.meadowNight`). Своё `--blur` темы — только при `data-blur="normal"`. **Правило:** любое значение, которое меняет игрок в «Внешнем виде», тема задаёт только под условием «по умолчанию» этой настройки. Проверка — скрипт кликов по каждой кнопке во всех 10 темах с замером видимого результата.
- **Настройки, которые задаёт сама тема** (в «Пикселе» — стекло, скругления, шрифт; в «Минимализме» — стекло), неактивны и подписаны (`lockedOption` в `app.js`): раньше кнопки нажимались и молча ничего не меняли.
- **Процессы записи и выход лаунчера:** Windows не завершает дочерние процессы вместе с родителем. Живые процессы FFmpeg гасятся в `process.on('exit')` (`LIVE_PROCS` в `memories.js`), буфер ограничен `-t 3600` и перезапускается — иначе после сбоя лаунчера FFmpeg писал бы экран до перезагрузки. Проверено вживую: после `process.exit` процесса FFmpeg нет.
- **`oldversions.test.js`** снова один раз упал в полном прогоне (30.10.2026), следующие 5 прогонов — зелёные; причина по-прежнему не найдена (см. выше).
- **Формат мира 26.x** (DataVersion 5000+): в level.dat больше нет Player/DayTime/SpawnX — игрок в `players/data/<uuid>.dat` (uuid из `Data.singleplayer_uuid`, 4 int), время в `data/minecraft/world_clocks.dat` (`total_ticks`), точка появления — `Data.spawn.pos`, регионы — `dimensions/minecraft/overworld/region`. Всё это читает `worlddata.readWorld`; новые места — только через него.
- **Палитра блоков в чанках 26.x**: элемент — строка, `{id, properties}` или `{"": имя}` (так игра пишет список из значений разных типов); раньше всегда `{Name, Properties}`. Упакованные блоки и карта высот читаются как Buffer (`parse(…, {rawLongs: true})`): через Number 64-битные слова теряют младшие биты.
- **«Новый мир» для вызова** — нет в летописи И моложе суток (`ticks < 24000`): иначе старые миры, впервые попавшие в летопись после обновления лаунчера, засчитывались бы как новые.
- **`processRssMb` асинхронный** (tasklist/ps): замер памяти в `perf.js` ждёт Promise; если ждать число — всегда 0.
- **Скин сборки** загружается в профиль только если `skins.active` другой: Mojang ограничивает частую смену (429).
- **Уведомление (toast)** не перехватывает клики (`pointer-events: none`): раньше 5 секунд закрывало кнопки внизу главной.
- **Главная:** карточки «Почему тормозило» и вызова — строкой `.home-notes` под главным блоком; в боковой колонке они вытягивали её и сталкивали «Играть» за край окна.
- **Пиксельный шрифт мелким кеглем нечитаем:** у Pixelify Sans на 12–14 px «2» похожа на «S», «с» — на «о». Пиксельные акценты делаются формой (прямые углы, торец снизу), а не шрифтом.
- **API GitHub без входа — 60 запросов в час на IP** (у игроков за VPN лимит часто уже исчерпан). FFmpeg берётся по прямым ссылкам выпуска `latest` и списку `checksums.sha256` рядом с архивами; размер — из `Content-Range` запроса одного байта.
- **ddagrab и номер монитора:** порядок мониторов DXGI и Windows может не совпадать, поэтому ddagrab — только при одном мониторе, иначе gdigrab (смещения от угла виртуального экрана, бывают отрицательные).
- **Серверные моды нужны одиночной игре.** Одиночная игра идёт на встроенном сервере: моды генерации мира (YUNG's, When Dungeons Arise, Structure Pool API) на Modrinth помечены `client_side: unsupported`, но в папку игры их класть надо. До 3.8.1 лаунчер их пропускал — структуры не появлялись, а мод, которому такая библиотека нужна, вылетал. Правило — `lock.inGame` (не ставится только `dedicated_server_only`, флаг `side.dedicated`). Гостю на чужом сервере (манифест комнаты) по-прежнему идут только моды с `onClient`.
- **Зависимость в каталоге без версии.** Iris 1.8.8 на Modrinth требует Sodium без `version_id`, планировщик берёт новейший Sodium 0.8.13, а в файле Iris записано `"sodium": "0.6.x"`. Поэтому версии сверяются по `fabric.mod.json` (`modlinks.satisfies`), а подходящая версия ищется по числам в номере версии каталога (`Services.versionFor`: «mc1.21.1-0.6.13-fabric» → 0.6.13) и проверяется уже по скачанному файлу. Версию одного мода подбираем один раз за проверку — иначе два мода с разными требованиями перебивали бы друг друга; второй требующий убирается.
- **Несколько копий библиотеки** (отдельный мод и вложенная в другой JAR) — Fabric берёт самую новую; проверка делает так же. Если подходит только отдельная библиотека, а её нет, она ставится (`wrong.nested`).
- **Разбор журнала Fabric:** строка «requires version 1.2.1 or later of structure_pool_api» раньше давала мод «version», и «Исправить» добавлял в сборку посторонний мод VerSion. Теперь у правил есть `all` (каждая строка — отдельная находка) и `unless`, а «Исправить» после вылета сначала проверяет файлы сборки (`fixTask` → `linkReport`/`linkFixTask`).
- **Настройки из админ-панели** пишутся в `server.properties` и в `easylauncher-server.json` в папке сервера. `startSession` перезаписывает server.properties своими значениями по умолчанию, поэтому выбор хозяина подмешивается из этого файла после них (`readOverrides`) — иначе перезапуск их сбрасывал.
- **Перезапуск сервера не закрывает комнату:** `Services.restartServer` ставит флаг `restarting`, и обработчик остановки сервера не вызывает `stopRoom`; после старта обновляется `host.targetPort`.
- **Правила игры зависят от версии:** в одних версиях `keepInventory`, в новых — `keep_inventory` и другие имена. `ServerAdmin.gamerules` пробует варианты и запоминает тот, что понял сервер; значение читается из строки журнала — отдельного API нет.
- **`tasklist` в окне Electron** отдаёт память как «35 924 КБ» в кодировке OEM, а не «35,924 K»: разбор берёт только цифры. Иначе память сервера показывалась 0.
- **`level-name` в server.properties** должен совпадать с папкой мира — иначе новый мир получает в level.dat имя «world». Миры, созданные до 3.8.0, так и называются «world»; админ-панель тогда показывает имя папки.
- **e2e иногда (редко) падал** из-за ошибки в консоли с неизвестным текстом. Не воспроизводилось 11+ прогонов подряд после фикса пустой картинки в `easyimg`. Если повторится, сохрани текст ошибки.
